# ApkCLI

[English](README.md) · **Русский**

ИИ-агент для программирования, который работает **на** Android-телефоне, а не
управляет им снаружи. Настоящие файлы, настоящая оболочка, настоящий редактор —
без root и без компьютера рядом.

Это как Cursor или Claude Code, только всё, что рассчитано на десктоп, заменено
тем, что работает внутри песочницы Android-приложения.

---

## Чем это отличается от чата, оформленного под редактор кода

| | |
| --- | --- |
| **Оболочка настоящая** | `sh -c` на устройстве, с PTY, так что `vi`, `less` и индикаторы прогресса ведут себя как положено. Встроенные инструменты запускаются из каталога нативных библиотек APK — единственного места, откуда без root разрешён exec. |
| **Окружение — это три каталога** | `files/home`, `files/usr`, `files/var`. А не россыпь по внешним каталогам приложения и кэшам, которые система может вычистить посреди сборки. |
| **Тяжёлая работа — на Rust** | Поиск по рабочей области (движок ripgrep, подключённый как библиотека), диффы, хранилище диалогов (SQLite + FTS5), подсчёт токенов, PTY, топология CPU. |
| **Нагрузкой управляют, а не надеются на лучшее** | Работа допускается по классам. Массовые задачи закреплены за малым кластером ядер и понижены в приоритете (nice); сборки *отклоняются*, когда устройство троттлит по температуре, а причина показывается и пользователю, и модели. |
| **Окно в миллион токенов расходуется по бюджету** | Сжатие контекста даёт структурированную сводку, в том числе о том, что уже пробовали и что не сработало, а дословная история остаётся в индексе, и агент может по ней искать. |
| **Подключение — это ключ** | Anthropic, OpenAI, OpenRouter и Kiro — известные схемы: вставьте ключ, и больше ничего не спросят. Любой другой сервер, совместимый с OpenAI или с Anthropic Messages, в облаке или в локальной сети по обычному HTTP (на публичный хост ключ никогда не уходит без шифрования), — это кастомное подключение со своим URL. Id модели вводить не нужно: список моделей и их метаданные читаются с эндпоинта и нигде не зашиты в код. |
| **Каждое сообщение — чекпоинт** | «Восстановить» над любым вашим сообщением возвращает чат, контекст агента и изменённые им файлы к состоянию до этого сообщения, а само сообщение — обратно в поле ввода. |
| **Поиску не нужен ключ** | `web_search` читает серверную lite-версию DuckDuckGo по HTTPS и разбирает её прямо на устройстве — без WebView и без аккаунта. Эндпоинт Brave/Tavily/SearXNG можно подключить по желанию. |

## Статус

Работает от начала до конца: настраиваете эндпоинт, начинаете сессию, агент
читает и правит файлы, запускает команды, а окно контекста под контролем.

| Область | Состояние |
| --- | --- |
| Ядро на Rust — хранилище, поиск, диффы, токены, PTY, планировщик, JNI | готово |
| Политика exec, окружение из трёх каталогов, bootstrap, шим `LD_PRELOAD` | готово |
| Регулятор нагрузки — пулы, привязка к ядрам, температурная политика | готово |
| Слой LLM — совместимый с OpenAI, Anthropic, Kiro (Amazon Q, AWS event-stream); SSE, повторы | готово; Kiro проверен на живом аккаунте на эмуляторе |
| Агент — системный промпт, 38 инструментов (41 в power), цикл, субагенты, подтверждения | готово |
| Пакеты — репозиторий Termux, разрешение зависимостей, перенос путей (power) | готово |
| Контекст — бюджет, сжатие, сводка, поиск по истории (FTS), память проекта | готово |
| UI — прототип дизайна перенесён 1:1: чёрная тема, сгенерированная из `design/tokens.json`, главный экран, проекты, рабочая область, настройки | готово |
| UI — чат с агентом (стриминг, рассуждения, карточки инструментов, диффы, индикатор контекста), чекпоинты, подключения по схемам | готово |
| UI — рабочая среда: проводник, редактор (sora, лексическая подсветка), изменяемое разделение экрана с чатом, просмотр и откат изменений агента | готово |
| UI — английский и русский, переключаются в «Настройки › Интерфейс» | готово |
| UI — терминал: несколько оболочек, рядом — фоновые процессы агента, цвет, Ctrl-C и клавиши, которых нет на экранной клавиатуре | готово |
| Агент — контекст окружения: открытые в редакторе файлы, активный из них и каждый терминал с тем, что в нём запущено | готово |
| UI — история чатов проекта: поиск, переименование, удаление; поиск по чату | готово |
| Изоляция PTY в процессе `:shell` | **ещё не сделано** — см. `docs/ru/ARCHITECTURE.md` |
| Сборка компилируется, Kotlin + Rust, debug и release | готово |
| Запуск на устройстве | проверен на эмуляторе API 34 (x86_64) — см. ниже |

### Что доказывает сборка

Всё компилируется и упаковывается с чистой установки тулчейна:

| | |
| --- | --- |
| `:core` и `:app` на Kotlin | ни ошибок, ни предупреждений |
| `:app:assemblePlayDebug` / `assemblePowerDebug` | по 22,3 МБ, targetSdk 36 / 28 |
| `:app:assemblePlayRelease` / `assemblePowerRelease` | по 10,5 МБ, R8 + сжатие ресурсов + lint-vital, подпись (v2) |
| Rust, все три ABI | arm64-v8a, armeabi-v7a, x86_64 линкуются |
| JNI-символы | 15/15 экспортированных имён совпадают с `Native.kt`, сверено по ELF |
| Выравнивание страниц 16 КБ | каждый сегмент `LOAD` на `0x4000` |
| `android:extractNativeLibs` | `true` в обоих итоговых манифестах — флаг, на котором держится вся схема запуска программ |

Первая сборка выявила пятнадцать настоящих дефектов. Среди них два, которые
проявляются только на 32 битах (на ILP32 у `RTLD_NEXT` другое значение, и
64-битная константа молча означает `RTLD_DEFAULT` и привела бы к бесконечной
рекурсии), ловушка лексера, где `/*` внутри комментария проглотил 50 строк
`app/build.gradle.kts`, и правила бэкапа, которые отверг lint. Все они
перечислены в `docs/ru/ARCHITECTURE.md`.

### Что проверено на эмуляторе, а что нет

Запуск на эмуляторе API 34 x86_64 (образ Pixel 6a), сборка power:

* Оболочка работает из `nativeLibraryDir` и `$PREFIX/bin`; пакеты Termux
  ставятся через `pkg_install`, и их программы запускаются (`untrusted_app_27`).
* PTY: `/dev/ptmx`, `fork`/`execve`, интерактивная оболочка в панели терминала
  с приглашением из `$PREFIX/etc/profile`, цветной вывод, Ctrl-C, вызов команды
  из истории с перерисовкой приглашения шире экрана, программа на переднем плане
  и рабочий каталог, прочитанные обратно из ядра.
* Сеть из оболочки (и почему `nc` из toybox на эмуляторе выглядит офлайн).
* Команды инструментов транслируют вывод в карточку чата, пока выполняются;
  команда, которая оставляет что-то в фоне (`cmd &`), возвращается сразу после
  завершения с пометкой, что было остановлено; по таймауту команда убивается
  вместе со всем, что она запустила; `web_search` завершается за секунды и
  имеет жёсткий лимит, как и любой инструмент.
* Карточка выполняющейся команды показывает, сколько она уже идёт, и последние
  строки её терминала: команды печатают в псевдотерминал, поэтому инструменты
  рисуют прогресс так же, как в окне терминала. Цикл `printf '\r…'` показал свои
  цвета, stderr в правильном порядке и одну строку прогресса, считающую на
  месте; `npm install` показал свой спиннер и закончил сводкой. `pkg_install`
  по ходу показывает строки самого установщика (`Downloaded 3/5 tree, 36 KB`,
  `Unpacking 1/5 oniguruma`). Индикаторы прогресса pip не проверялись.
* Чат остаётся внизу после переключения вкладок и пока выполняется вызов при
  открытой клавиатуре.
* PostgreSQL 18 из Termux, под обоими именами пакета: `pkg_install postgresql`,
  `initdb`, `pg_ctl start`, запрос в `psql`, `pg_ctl stop`.
* Иконки файлов: родной иконочный шрифт Seti из VS Code и его цвета в
  проводнике (API 34).
* Диффы нумеруют старые и новые строки в двух колонках, как на GitHub
  (проверено на правке, которая заменила три строки двумя).
* Живой вывод под выполняющейся командой прокручивается назад и остаётся на
  месте; пока стримится ответ или рассуждение, чат остаётся там, куда его
  прокрутил пользователь, и снова следует за концом, когда к нему вернутся.
* Команды каждого чата появляются в панели терминала как «Агент · …» со своим
  выводом и кодом завершения, и Ctrl-C там прерывает текущую.
* Скриншот, отправленный без текста, дошёл до эндпоинта одной частью с
  изображением JPEG.
* Runner установил `python`, не спрашивая, при старых сохранённых записях
  «спрашивать» в настройках; переключение с Engineer на Runner во время
  выполнения команды дало следующей команде выполниться без вопроса.
* `pip install pydantic` за 20 с установил pydantic 2.12.5 с готовым
  pydantic-core 2.41.5, и оба импортировались.
* `octocat/Hello-World` открыт с GitHub как проект.
* Память: факты, сохранённые агентом, глобальные и для проекта, появляются в
  промпте следующего запроса и в панели памяти.
* Обновлённый UI против скриптового локального сервера: окна подключений
  (форма из одного ключа, проверки кастомной формы), подтверждение, панель
  изменений и бейдж на вкладке «Файлы», восстановление чекпоинта, которое
  удалило записанный агентом файл, убрало сообщения после него и вернуло текст
  в поле ввода. Дерево файлов и редактор во вкладке «Файлы», зелёное
  приглашение терминала с `ls -la`.
* Kiro на живом аккаунте: чаты, вызовы инструментов и замеры кэша промпта в
  `docs/ru/PROVIDERS.md`.

Ещё не доказано:

* Любое физическое устройство и `untrusted_app_3x` (сборка play) дальше
  запуска.
* Переписывание `#!/bin/sh` шимом `LD_PRELOAD` — именно эта часть.
* Переживёт ли подсветка TextMate R8: релизная сборка пишет в лог
  `R8: org.joni.ast.QuantifierNode.<clinit>() does not type check and will be
  assumed to be unreachable` — это транзитивная зависимость поддержки TextMate
  в sora-editor. Безвредно, если этот путь действительно мёртвый, и падение,
  если нет.
* Сжатие контекста на настоящей длинной сессии и большинство путей обработки
  ошибок в цикле агента.
* Блок `<environment-context>` внутри живого запроса. Его текст покрыт
  юнит-тестами; ход в приложении, который его отправляет, не записывался.
* Адаптивное мышление Anthropic на живом API. Оно покрыто юнит-тестами только
  на уровне формата обмена (чему оно следует, описано в
  `docs/ru/PROVIDERS.md`).

## Сборка

### Что нужно

| Инструмент | Версия | Примечания |
| --- | --- | --- |
| JDK | 17 | AGP 9.1 требует минимум 17; собрано на Temurin 17.0.20.1 |
| Gradle | 9.8.0 | через `./gradlew`; для AGP 9.1.1 нужен 9.3.1+ |
| Android SDK | platform 36, build-tools 36.0.0 | |
| Android NDK | 28.2.13676358 | версия по умолчанию в AGP 9.1; нужна для выравнивания страниц 16 КБ |
| Rust | 1.85+ | собрано на 1.99.0. `rustup target add aarch64-linux-android x86_64-linux-android` |
| cargo-ndk | 4.1.2 | `cargo install cargo-ndk` |

На Windows без Visual Studio ставьте Rust с GNU-хостом, чтобы у скриптов
`build.rs` был линкер для хоста (`libsqlite3-sys` компилирует SQLite из
исходников на C):

```
rustup-init.exe -y --default-host x86_64-pc-windows-gnu --profile minimal
```

Проверить, что на самом деле установлено:

```sh
./gradlew envReport
```

### Статический аудит

Три проверки на Python ловят то, о чём компилятор не скажет или скажет так, что
укажет не на ту строку. Им не нужно ничего, кроме Python 3.

```sh
python tools/audit.py                   # ненулевой код выхода, если есть находки
python tools/check_nested_comments.py   # также запускается из audit.py
python tools/test_zero_runpath.py       # проверяет патчер ELF
```

`audit.py` проверяет то, чего не видно при перечитывании: импорты в Kotlin
символов проекта, которые нигде не объявлены; ссылки `R.*` без подходящего
ресурса; алиасы `libs.*`, которых нет в каталоге версий; объявления `mod` в
Rust без файла; имена JNI-символов, которые расходятся между `ffi.rs` и
`Native.kt`; классы из `android:name` в манифесте, которых не существует;
несбалансированные скобки; неиспользуемые импорты и короткий список
рискованных паттернов. Он понимает receiver'ы extension-функций Kotlin, сырые
строки и лайфтаймы Rust: ошибки в этом дали 77 фантомных находок при первом
запуске, а сканирование `app/build/intermediates` позже — ещё 18, поэтому весь
обход файлов идёт через один отфильтрованный `walk()`.

`check_nested_comments.py` — та проверка, которая себя окупает. И Kotlin, и
Rust допускают **вложенные** `/* */`, поэтому glob в тексте комментария
(`/system/bin/*`) открывает второй комментарий, и всё до следующего `*/`
пропадает. В `app/build.gradle.kts` этот `*/` нашёлся внутри строки
`"**/*.so"` пятьюдесятью строками ниже, и компилятор выдал 232 ошибки, ни одной
рядом с настоящей.

`test_zero_runpath.py` собирает синтетические 64- и 32-битные ELF с
`DT_RUNPATH` и `DT_RPATH`, запускает патчер и проверяет, что теги обнулены,
`DT_NEEDED` не тронут, а размер файла не изменился. Последнее и есть весь смысл
отказа от `patchelf`.

### Команды сборки

```sh
# только arm64 — разумный выбор по умолчанию в 2026 году
./gradlew :app:assemblePlayDebug

# итерации только над UI, совсем без шага Rust
./gradlew :app:assemblePlayDebug -Papkcli.buildRust=false
```

С `apkcli.buildRust=false` приложение всё равно запускается: оценка токенов и
поиск переходят на реализации на Kotlin, а хранилище диалогов при старте
сообщает понятную ошибку, а не падает.

### Два флейвора

```sh
./gradlew :app:assemblePlayDebug    # targetSdk 36 — можно публиковать, exec ограничен
./gradlew :app:assemblePowerDebug   # targetSdk 28 — только ручная установка, exec без ограничений
```

Это **главное** решение в проекте, а не деталь упаковки.

Начиная с Android 10, SELinux запрещает `execve()` для любого файла в каталоге
данных приложения. Приложения с targetSdk 28 и ниже попадают в домен, где это
ещё разрешено.

* **play** — может запускать только бинарники, поставляемые внутри APK, и то,
  что лежит в `/system/bin`. Установить пакеты во время работы нельзя, поэтому
  инструменты для пакетов не предлагаются, а системный промпт объясняет почему.
* **power** — устанавливает пакеты Termux (`python` с `pip`, `nodejs` с `npm`,
  `git`, `clang`, … около 3000) через `pkg_install`, `pkg_search` и
  `pkg_remove` и запускает их из `$PREFIX`. По-прежнему ставится на Android 15
  и 16, которые отказывают только при `targetSdk < 24`. В Play не
  опубликовать.

Подробно: [docs/ru/ANDROID_EXEC_NOTES.md](docs/ru/ANDROID_EXEC_NOTES.md).

### Пакеты (power)

Ни apt, ни dpkg нет: в оба вкомпилированы пути Termux. Приложение само читает
индекс `Packages` репозитория (сверяя его с SHA-256 из `Release`), вычисляет
замыкание зависимостей, проверяет каждый `.deb` по индексу и распаковывает его
в `$PREFIX`, переписывая `/data/data/com.termux/files/usr`. В релизной сборке
путь переписывается на `/data/data/dev.apkcli.power/usr` — те же 31 символ,
симлинк на настоящий префикс, — так что даже пути внутри бинарников
исправляются на месте. Сборка, у которой имя пакета для этого слишком длинное
(отладочная), или вторичный пользователь вместо этого получают прямые пути и
runpath с `$ORIGIN`, плюс псевдонимы той же длины для каталогов верхнего уровня
префикса, где они помещаются (`$PREFIX/tmp` →
`/data/data/dev.apkcli.power.debug/t`, `bin` → `.../b`…). `$PREFIX/tmp`
вкомпилирован в библиотеки POSIX-семафоров и разделяемой памяти Termux;
PostgreSQL, не достучавшись до него, не падает, а бесконечно повторяет попытки,
поэтому `initdb` раньше зависал на «selecting default max_connections».

Не сделано: GPG-подпись репозитория не проверяется (загрузку защищают HTTPS и
контрольные суммы), и скрипты сопровождающих Termux не запускаются — для
распространённых пакетов они только печатают заметки или предкомпилируют
Python. Установленные файлы учитываются в
`$PREFIX/var/lib/apkcli/packages.json`.

При первом запуске pip один раз получает `~/.config/pip/pip.conf`: индекс
готовых wheel-пакетов для Android от [Termux User
Repository](https://termux-user-repository.github.io/pypi/) как дополнительный
индекс и `only-binary` для покрытых им пакетов на Rust (pydantic-core,
tokenizers, tiktoken, watchfiles), которые иначе компилируются час или падают
по таймауту. Это индекс сообщества; удалите файл, чтобы ставить пакеты только с
PyPI.

### Встраивание консольных утилит

Приложение работает и без встроенных утилит: тогда оно обходится
`/system/bin/sh` (mksh) и toybox, который на современном устройстве покрывает
около 150 апплетов. Чтобы добавить полноценные инструменты:

```sh
pwsh tools/fetch-prebuilts.ps1 -Abi arm64-v8a -Packages busybox,git
```

Они должны быть слинкованы с bionic, поэтому скрипт берёт пакеты Termux, а не
собирает их на Linux-десктопе. См.
[native/prebuilt/README.ru.md](native/prebuilt/README.ru.md).

## Первый запуск

1. **Настройки → Подключения.** Сначала список пуст. Добавьте Anthropic,
   OpenAI, OpenRouter или Kiro: одно поле — ключ.
   Kiro принимает то же, что Kiro Account Manager: `refreshToken` аккаунта из
   Kiro IDE (`~/.aws/sso/cache/kiro-auth-token.json`) при входе через Google
   или GitHub, а для Builder ID — то же вместе с его `clientId` и
   `clientSecret`, в виде JSON или в формате экспорта менеджера. Обмен токена
   может разлогинить IDE, и форма об этом предупреждает. «Кастомный эндпоинт» —
   для локального сервера или прокси: он спрашивает URL и формат. Подключение с
   ключом становится активным, если у активного ключа нет.
2. **Модели.** Id модели не нужен никогда. При сохранении ключ проверяется и
   загружается список моделей, выбирается модель по умолчанию, а окно выбора
   модели переключает между ними; если к отправке сообщения список всё ещё
   пуст, он загружается в этот момент. Обнаружение понимает форматы списков
   OpenRouter, OpenAI, Anthropic (постранично), Kiro, vLLM, LM Studio,
   llama.cpp, Ollama, Together (голый массив), Groq, Mistral, Fireworks,
   DeepInfra, Gemini и LiteLLM и отбрасывает то, что эндпоинт помечает как
   модели изображений, речи, эмбеддингов или поиска. OpenRouter, Anthropic и
   Kiro сообщают окна контекста прямо в списке; окно, которое пока лишь
   оценка, показывается в окне выбора модели как «≈», а первая ошибка
   переполнения сообщает приложению настоящее число.
3. **Проекты.** Главный экран открывает проект, создаёт новый или клонирует
   публичный репозиторий с GitHub (файлы, без истории git); список проектов
   также копирует папку с устройства. Проекты лежат в `~/projects/<name>`.
4. **Рабочая область.** Три вкладки: «Агент», «Файлы» и «Терминал»; на
   планшете или в альбомной ориентации агент делит экран с одной из двух
   других. Поле ввода прикрепляет фото и скриншоты, а значок книги показывает,
   что помнит агент, и даёт это править. Строка «Чекпоинт · Восстановить» над
   каждым вашим сообщением возвращает чат, контекст и сделанные агентом
   изменения файлов к состоянию до него.

### Режимы агента

Режим определяет, когда агент спрашивает разрешения. Чтение, поиск и просмотр
списков не спрашивают никогда. Названия режимов на всех языках одинаковые.

| Режим | Спрашивает | Для чего |
| --- | --- | --- |
| Confirm | Перед каждым изменением: запись, перемещение или удаление файла, команда, пакет, субагент. | По умолчанию. Вы подтверждаете изменения по ходу работы. |
| From Rules | Только о том, что не отмечено в разделе «Настройки › Правила». После установки отмечены правка файлов и субагенты. | Повседневная работа: чему доверяете, идёт само, остальное ждёт. |
| Bypass Mode | Ни о чём, включая удаление. | Довести задачу до конца. Правки файлов можно откатить, удалённую папку — нет. |

Смена режима действует и на текущий ход. Для исследования субагенты используют
Исследователя (Explorer), который только читает. Настройки из сборок с Engineer
и Runner переносятся: Engineer становится Confirm, Runner — Bypass Mode.

## Структура

```
app/                      UI на Compose
core/                     Всё остальное
  agent/                  Промпт, инструменты, цикл, сжатие контекста
  llm/                    Эндпоинты, протоколы, стриминг
  runtime/                Окружение, политика exec, оболочка, PTY
  sched/                  Регулятор нагрузки
  store/                  Хранилище диалогов, настройки, секреты
  web/                    Загрузка страниц и извлечение текста из HTML
native/
  apkcli-core/            Rust: хранилище, поиск, диффы, токены, PTY, планировщик
  execshim/               Шим LD_PRELOAD для shebang и путей /bin
  prebuilt/               Готовые бинарники под bionic (скачиваются, не коммитятся)
docs/
tools/
```
