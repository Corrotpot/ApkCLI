# Политика безопасности

[English](SECURITY.md) · **Русский**

## Как сообщить об уязвимости

Сообщите о ней приватно, через форму GitHub
[Report a vulnerability](https://github.com/Corrotpot/ApkCLI/security/advisories/new).
То, что отправлено через неё, видит только сопровождающий проекта. Пожалуйста,
не открывайте об этом публичный issue, pull request или обсуждение.

Полезное сообщение говорит:

* что может сделать атакующий и что ему для этого нужно: веб-страница, которую
  читает агент, файл в проекте, враждебный эндпоинт, другое приложение на
  устройстве;
* как это воспроизвести, или proof of concept;
* флейвор сборки (play или power), коммит, устройство или эмулятор и его
  версию Android.

Никогда не вставляйте в сообщение настоящий ключ или токен. Если ключ утёк,
сначала отзовите его у провайдера.

Гарантированного срока ответа нет. Ответ придёт в самом сообщении, а когда
выйдет исправление, оно будет опубликовано как security advisory — с именем
автора сообщения, если он этого хочет.

## Поддерживаемые версии

Релизов пока нет. Исправления получает только последний коммит в `main`.

## Что считается уязвимостью

ApkCLI запускает ИИ-агента с оболочкой, файлами ваших проектов и вашими
API-ключами. Уязвимости — это:

* API-ключ или токен аккаунта уходит из приложения куда-либо, кроме своего
  подключения: в логи, бэкапы, экспорт или на другой хост.
* Ключ отправляется по обычному HTTP на публичный хост. Обычный HTTP разрешён
  только для частных адресов (`NetworkHosts`).
* Вызов инструмента, который что-то меняет, выполняется без подтверждения,
  которого требует режим: любое изменение в Confirm или неотмеченный вид
  изменений в From Rules.
* Доступ к файлам за пределами `~/projects` через провайдер документов
  (`ProjectDocuments`) или запись за пределы целевой папки при импорте проекта
  (`..` в путях, симлинки).
* Другое приложение на устройстве получает доступ к данным этого приложения,
  ключам или оболочке через экспортированный компонент.

## Что не считается

* То, что делает Bypass Mode. Он по замыслу ни о чём не спрашивает, и его
  описание об этом говорит.
* Prompt injection сама по себе. Страница или файл, которые уговорили модель
  на что-то, — известное свойство LLM-агентов; уязвимостью это становится,
  когда обходит подтверждение, которое режим должен был запросить.
* То, что провайдер модели делает с отправленными ему запросами.
* Уязвимости в пакетах Termux, установленных через `pkg_install`. О них
  сообщайте в [Termux](https://github.com/termux/termux-packages).
* Атаки, которым нужен root или разблокированное устройство в руках
  атакующего.
* То, что сборка power нацелена на API 28. Именно это позволяет ей запускать
  установленные программы; см.
  [docs/ru/ANDROID_EXEC_NOTES.md](docs/ru/ANDROID_EXEC_NOTES.md).
