# Готовые (prebuilt) бинарники для устройства

[English](README.md) · **Русский**

В этом каталоге лежат дополнительные утилиты командной строки, которые
поставляются внутри APK. В свежем клоне он пуст — наборы файлов скачивает
`tools/fetch-prebuilts.ps1` (Windows, PowerShell).

## Почему их нельзя просто скачать во время выполнения

При `targetSdk >= 29` каталог данных приложения имеет метку SELinux
`app_data_file`, которая не даёт разрешения `execute_no_trans`. Бинарник,
записанный туда во время выполнения, запустить нельзя, что бы ни говорили его
биты режима. Единственное место, доступное приложению без root, куда можно
записать при установке и откуда можно запускать во время выполнения, —
`nativeLibraryDir`; его заполняет установщик из `lib/<abi>/` внутри APK.

Следствие: каждый исполняемый файл должен оказаться **в APK на этапе сборки** и
называться `lib<something>.so`, потому что установщик распаковывает только
файлы, подходящие под этот шаблон.

## Соглашение об именах

```
native/prebuilt/arm64-v8a/libgit.so      -> $PREFIX/bin/git
native/prebuilt/arm64-v8a/librg.so       -> $PREFIX/bin/rg
native/prebuilt/arm64-v8a/libbusybox.so  -> $PREFIX/bin/{sh,ls,sed,awk,...}
```

`Bootstrap.kt` при первом запуске создаёт симлинки `$PREFIX/bin/*`, указывающие
в `nativeLibraryDir`, и пересоздаёт их при каждой смене кода версии
приложения, потому что при обновлении приложения `nativeLibraryDir` переезжает
на новый путь.

## Откуда берутся бинарники

Из репозитория пакетов Termux, потому что эти сборки уже слинкованы с
**bionic**, а не с glibc. Бинарник, собранный на настольном Linux, запрашивает
в качестве ELF-интерпретатора `/lib/ld-linux-aarch64.so.1`, которого на
Android нет; бинарники Android запрашивают `/system/bin/linker64`.

Скрипт загрузки скачивает пакеты `.deb` с `packages.termux.dev`, распаковывает
`data.tar.xz` и переименовывает бинарники. Затем ему приходится исправить ещё
одну вещь:

В бинарниках Termux зашит `DT_RUNPATH`, равный
`/data/data/com.termux/files/usr/lib`. На устройстве без Termux такого каталога
нет, а линкер пробует его первым. Исправление — обнулить поле `d_val` у
динамических записей `DT_RPATH` / `DT_RUNPATH` **на месте**. Не используйте
`patchelf --remove-rpath`: он переписывает раскладку сегментов `PT_LOAD`, а
Android 11+ отвергает ELF-файлы с неожиданным числом сегментов.

## Минимально необходимый набор

Приложение работает и без всего этого — в качестве запасного варианта оно
использует `/system/bin/sh` (mksh) плюс `/system/bin/toybox`, который на
современном устройстве покрывает примерно 150 апплетов coreutils. Именно
встроенный набор превращает его из «оболочки» в «среду разработки»:

| Бинарник | Размер (arm64) | Зачем |
| --- | --- | --- |
| `libbusybox.so` | ~1,1 МБ | Полноценный `ash`, настоящие `sed`/`awk`/`grep`/`tar`, `vi` |
| `libgit.so` | ~4,5 МБ | Контроль версий. Рядом нужны `libz`, `libcurl`, `libpcre2` |
| `librg.so` | ~4,8 МБ | Необязателен: Rust-ядро уже слинковано с движком ripgrep |
| `libpython.so` | ~25 МБ | Имеет смысл, только если нужен Python; тянет за собой большой набор файлов stdlib |

Следите за размером APK: всё это — для каждого ABI отдельно. Поставлять только
arm64 — разумный вариант по умолчанию в 2026 году.

## Проверка набора файлов, прежде чем ему доверять

```sh
# ELF-интерпретатором должен быть линкер Android
readelf -l libgit.so | grep interpreter      # => /system/bin/linker64

# Не осталось RUNPATH от Termux
readelf -d libgit.so | grep -E 'RPATH|RUNPATH'   # => ничего или пустое значение

# Выровнено по 16 КБ (Play требует с 2027-02-01)
readelf -lW libgit.so | grep LOAD            # => Align 0x4000
```
